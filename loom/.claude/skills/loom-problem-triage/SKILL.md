# Problem triage

This is the judgement that everything downstream inherits. Tune it against past
engagements before trusting it (phase 3).

## Before triage: is it one problem?

Split a problem when parts have different owners or different evidence. Merge problems
that are the same root cause seen from two roles. State each problem as a situation, not a
solution ("New store staff cannot work unsupervised for six weeks", not "We need a buddy
app").

## The test

A problem is **offline** when all of these hold:

1. One owner can decide it. They have the authority and the budget.
2. The others only need informing, not persuading.
3. The answer is mostly known, or a single expert can supply it.
4. Getting it wrong is cheap to reverse.

A problem is **co-creation** when any of these hold:

1. Several parties hold part of the answer (the knowledge is distributed).
2. Agreement matters as much as the answer (adoption depends on buy-in).
3. The problem crosses a boundary: two functions, two sites, client and partner.
4. The owner is contested or nobody owns it.
5. Previous attempts failed for reasons of ownership or buy-in (check the archive findings).

## Tie-breakers

- When unsure, ask: "If the owner decided this alone tomorrow and emailed everyone, would it
  stick?" Yes → offline. No → co-creation.
- A problem with no clear owner is co-creation, and "agree the owner" is part of it.
- Do not send a problem to the room because it is important. Importance is not the test;
  distribution of knowledge and need for agreement are.
- Do not keep a problem offline because it is politically awkward. Awkward and contested is
  co-creation.

## Evidence

Every problem cites `evidence_refs` that resolve. Weight: responses and documents over a
single remark; claims below 0.5 confidence never carry a problem alone. If a problem rests
on thin evidence, say so in `why` and in the handoff rather than dropping it silently.

## Worked examples

- "Laptops arrive a week late": IT owns provisioning, procurement owns ordering. If the
  archive shows IT and procurement already agreed an SLA elsewhere → offline, owner IT, draft
  the message. If nobody owns the handover between them → co-creation.
- "Nobody owns the buddy system": contested ownership, failed before for lack of an owner →
  co-creation.
- "The welcome pack is outdated": HR owns it, others only need the new version → offline.

## Offline drafts

For each offline problem, draft the message: to whom, what we found (with evidence), what we
ask them to decide, by when. Plain, short, no EC jargon.
